## 2. 理论学习（Theory）

### 2.1 指令到执行：命令帧 → 占空比

协议 0x201 的 data[1..2] 是目标速度（0~1000），Node2 收到后直接映射为 PWM 占空比（0~100%），完成"应用层指令 → 物理执行"的转换。速度 0 = 停转，500 = 半速，1000 = 全速。

### 2.2 真实反馈：编码器 → 0x202

0x202 从"模拟递增速度"改为"编码器每秒计数值"：每 1s 读取 TIM3 CNT，与上次差值即每秒计数。该值后续（Day25）通过每转标定换算为 RPM。

### 2.3 默认停转

上电默认占空比 0，电机不转；只有收到 0x201 命令才转。这符合工业惯例：执行器不应在无指令时自行动作。

## 4. 代码实现

### 4.1 命令驱动电机（CanRxTask）

```c
if ((frame.id == CAN_CMD_ID) && (frame.data[0] == 0x01U))
{
    g_speed = (uint16_t)(frame.data[1] | ((uint16_t)frame.data[2] << 8));
    MotorSetDuty(g_speed);          /* 0~1000 = 0~100% 占空比 */
    MotorSetDir(1U);                /* 固定正向 */
    CanSendMotorData(g_speed);      /* 应答回传设定值 */
}
```

### 4.2 真实编码器速度上报（CanTxTask）

```c
enc   = MotorGetCount();
delta = enc - last_enc;
last_enc = enc;
if (delta < 0) delta = -delta;      /* 速度取绝对值 */
if (delta > 0xFFFF) delta = 0xFFFF;
CanSendMotorData((uint16_t)delta);  /* 0x202 = 每秒编码器计数 */
```

移除：模拟速度自动递增、命令速度 5s 覆盖逻辑、上电 30% 测试占空比。

## 6. 遇到的问题与解决（Problems & Solutions）

### Problem 1：真实速度与协议字段不匹配的风险

问题：编码器每秒计数可能超过 65535，2 字节字段会溢出。

应对：上报前钳位到 0xFFFF；Day25 标定后按 RPM 上报（数值远小于计数），并视需要调整协议。

## 8. 工程总结（Engineering Summary）

## 应用层与物理层解耦

主控只发"目标速度"（0~1000 抽象值），Node2 负责映射为 PWM 占空比——命令协议不必关心具体驱动细节，这是分层设计的体现。

## 执行器默认安全态

无指令不动，避免上电误动作，工业安全的基本意识。

## 9. 面试问答（Interview Prep）

### Q1：主控怎么控制远端电机？

答题要点：

* 主控发 0x201 命令帧（目标速度）
* 电机节点解析命令、映射为 PWM 占空比、驱动 L298N
* 编码器测速后经 0x202 回报，形成控制闭环

### Q2：为什么执行器要默认停转？

答题要点：

* 上电无指令动作可能造成安全事故
* 工业执行器通常要求"无指令 = 安全态"
