# 项目叙事（简历版 + 口述版）

> 用于简历和面试的项目表达，按"背景 / 技术栈 / 职责 / 难点 / 结果"五部分整理。

## 1. 五部分整理

### 背景

模拟工业现场"传感器采集 → 总线通信 → 主控决策 → 执行器响应"的分布式控制链路，以 40 天学习项目的形式完成一主两从的三节点 CAN 工业控制系统原型。

### 技术栈

STM32F407ZGT6 / STM32F103C8T6 · FreeRTOS（CMSIS_V1）· CAN 2.0B（500kbps）· STM32 HAL 库 · PWM · 编码器 · PID · UART IAP · Python（pyserial）

### 职责

* 主控：FreeRTOS 多任务调度（收发/控制/故障监测/调试）、心跳与命令帧、节点离线检测
* 传感器节点：温度上报 + MPU6050 六轴数据采集与 CAN 上报
* 电机节点：PWM 驱动（L298N）、编码器测速（TIM3 4 倍频）、PID 速度闭环
* 独立实现 UART IAP Bootloader 与 Python 上位机升级工具

### 难点与解决

* F103 CAN_RX 必须配输入模式（F1 无 AF 选择寄存器），修复后节点收发正常
* L298N 驱动极性反转：IN2 恒高时速度与占空比成反比（0=全速、满占空=刹车），改为正向 IN2 拉低 + duty 钳位
* 杂牌电机编码器标定：数圈法 + 转动法双方法实测 PPR=1079，0x202 上报 RPM
* 编码器反馈受 PWM 噪声污染：内部上拉 + EMA 平滑 + PWM 降频（PID 实测延后）
* IAP 协议设计：2 字节长度字段放不下大镜像，用 DATA 携带 4 字节总长 + CRC32 全镜像校验

### 结果

* 三节点 CAN 500kbps 组网打通，心跳/离线检测与自动恢复
* 30 分钟压力测试错误计数 0
* 编码器标定完成（PPR=1079），速度以 RPM 上报
* PID 速度闭环代码实现（增量式 + 积分分离 + 限幅）
* IAP Bootloader 完整实现（分区/跳转/升级协议/CRC32/上位机）

## 2. 简历版（一段）

基于 STM32F407 + STM32F103 + FreeRTOS 设计并实现三节点 CAN 工业控制系统。系统采用一主两从架构，主控节点负责 CAN 总线调度、命令下发与故障监测，传感器节点完成温度与 MPU6050 六轴数据采集上报，电机节点实现 PWM 电机驱动、编码器测速与 PID 速度闭环（代码实现）。设计自定义 CAN 应用层协议（500kbps），实现心跳检测、节点离线识别与自动恢复，30 分钟压力测试错误计数为 0；并实现 UART IAP Bootloader（Flash 分区、CRC32 校验、Python 上位机升级工具）。

## 3. 口述版（约 1 分钟）

### 开场（30 秒：项目是什么）

"这个项目是我用 STM32 做的三节点 CAN 工业控制系统原型，模拟工业现场的分布式控制：一块 F407 做主控，两块 F103 分别做传感器节点和电机节点，通过 500kbps 的 CAN 总线连起来。整体用 FreeRTOS 做任务调度，通信走我自己设计的 CAN 应用层协议，包括心跳、命令和数据帧。"

### 我的职责与难点（30 秒）

"我主要负责主控的调度和故障监测、电机节点的 PWM 驱动和编码器测速，以及整套 IAP 升级。过程中踩了几个坑：一个是 F103 的 CAN 接收引脚配置错了会卡初始化，我对照手册修成了输入模式；另一个是 L298N 驱动极性反了，0 占空比反而全速转，我通过分析 H 桥逻辑改成了正确的方向控制。编码器是杂牌电机，参数未知，我用数圈法和转动法交叉实测标定了每转脉冲数，最后把速度换算成 RPM 上报。"

### 收尾（结果）

"最终三节点组网稳定，30 分钟压力测试错误计数为 0，心跳和离线检测都能工作；我还独立完成了 IAP Bootloader，包括 Flash 分区、CRC32 校验和 Python 上位机升级工具，整个链路从代码到文档都比较完整。"

> 注意：PID 闭环为代码实现、实测延后（编码器噪声问题待处理）；口述时按实际进度表述，不要声称"PID 已调通"。
