## 2. 系统最终状态速查

### 2.1 CAN 应用层协议

| 帧 ID | 方向 | DLC | 内容 |
|---|---|---|---|
| 0x100 | F407 → 总线 | 8 | 心跳：seq(2B) + 0x55AA(2B) + 预留(4B)，1s |
| 0x101 | F407 → Node1 | 1 | 命令：data[0]=0x01 请求上报温度 |
| 0x102 | Node1 → F407 | 2 | 温度：temp(2B 小端)，1s |
| 0x201 | F407 → Node2 | 3 | 命令：data[0]=0x01 设置速度，data[1..2]=目标速度(2B 小端) |
| 0x202 | Node2 → F407 | 2 | 速度：speed(2B 小端)，1s |

### 2.2 数据流

```text
Node1 温度(0x102) ─┐
                    ├─→ F407 CanRxTask ─→ 系统状态表 ─→ [DEBUG]
Node2 速度(0x202) ─┘

F407 CanTxTask ──→ 0x100 心跳(1s) / 0x101、0x201 命令(每 5s 交替)
Node1/Node2 收到命令 → 立即应答对应数据帧
```

### 2.3 在线判定

主控记录每个节点最近一帧的接收 tick，超过 5s 未收到判离线（状态翻转才打印告警），恢复上报自动回到在线并清除离线标志。

## 3. 排障复盘（本阶段最高价值的部分）

| # | 问题 | 根因 | 解决 | 教训 |
|---|---|---|---|---|
| 1 | F103 CAN 初始化卡死（INAK=1），耗时两天 | 误调用 `__HAL_AFIO_REMAP_CAN1_1()` 把 CAN 挪到 PB8/PB9；F1 无 AF 选择寄存器，RX 必须配 `GPIO_MODE_INPUT`；ST-LINK DBF 冻结位干扰判断 | 删除重映射、RX 改输入模式、启动清 DBF | 跨系列照抄 F4 配置是 F1 最常见坑；调试时先排除调试器干扰 |
| 2 | 三节点接面包板后总线全不通，三天 | 面包板行/列方向理解错误，中间凹槽两侧插孔不连通 | 修正接线方向 | 硬件排障先确认"物理拓扑是否真的连通" |
| 3 | 主控收发正常但节点不发 | 错误中断把 HAL State 锁死为 ERROR | ErrorCallback 恢复 READY；AutoBusOff=ENABLE | 中断回调要恢复状态机 |
| 4 | 串口打印交错丢字 | ISR 中 printf 与任务打印抢占 UART | ISR 只投递队列，错误详情由任务周期读 ESR 打印 | 中断不做耗时/共享资源操作 |
| 5 | DEBUG 显示 speed=0 | 0x202 解析沿用旧 4 字节格式，协议已改为 2 字节 | 按协议文档修正解析 | 协议文档与代码必须逐帧核对 |
| 6 | 节点在线但仍显示 OFFLINE | 离线标志锁存无清除逻辑 | 全部恢复在线后自动清除 | 状态标志要考虑"恢复路径" |
| 7 | 实验 D 中 TEC=0 而 REC=40 | 主控 CANH 断开后接收侧信号畸变累积 REC；TEC 未按预期增长原因待深挖 | 记录现象，未阻塞结论 | 错误计数时序需抓完整 ESR 变化，留作进阶课题 |

## 4. 工程方法论沉淀

* **先单机环回，再上总线组网**：隔离"外设问题"与"总线问题"
* **逐节点隔离实验**：每节点单独接分析仪都通 → 问题必在公共部分（面包板/终端电阻）
* **故障定位靠交叉信息**：单节点离线 vs 主控报 ACK 错误（LEC=3）+ 全离线，指向不同故障点
* **终端电阻**：高速 CAN 两端各 120Ω；短距离低速率下分析仪自带单终端可工作
* **ISR 最小化**：中断只投递，业务交给任务
* **协议文档驱动实现**：帧 ID、DLC、字节序先成文，实现逐字段核对

## 5. 面试价值（能讲的真实故事）

1. **"我独立解决过 F1 CAN 初始化卡死"**：能讲 GPIO_MODE_INPUT vs AF_PP 的寄存器级原因
2. **"我用逐节点隔离法三天定位到面包板方向错误"**：展示系统化排障而不是乱试
3. **"我的主控有 5s 心跳超时离线检测"**：数据新鲜度 + 状态翻转告警
4. **"我做了 30 分钟压力测试，错误计数保持 0"**：稳定性的实证
5. **"我实现过请求/应答命令帧协议"**：命令码 + 参数 + 应答三要素，可直接迁移到电机控制

## 6. 遗留与改进方向

* TEC=0/REC=40 的精确错误计数时序未深挖（进阶课题）
* 命令帧暂无超时重试、序列号、CRC 校验（工业可靠通信的可扩展点）
* Node1 温度、Node2 速度为模拟数据，尚未接真实传感器/电机（Phase 4 目标）
* MPU6050 未接入（Phase 4 规划）

## 7. 阶段衔接

Phase 3 为 Phase 4（电机 PID 闭环）留下了完整基础：

* 0x201 命令帧 = 主控下发目标速度的通道
* 0x202 数据帧 = 电机节点回报速度的通道
* 心跳/离线检测 = 电机节点故障监控框架
* 三节点总线 + 终端电阻 + 500kbps = 已跑通 30 分钟的稳定物理层
