## 2. 理论学习（Theory）

### 2.1 CAN 帧格式

标准数据帧由以下段依次组成：

```text
SOF(1) → 仲裁段(ID 11位 + RTR) → 控制段(IDE + 保留位 + DLC 4位)
       → 数据段(0~8 字节) → CRC段(15位CRC + 定界符)
       → ACK段(应答槽 + 定界符) → EOF(7 隐性位)
```

代码中的对应字段：

* `tx.IDE = CAN_ID_STD`：标准帧 11 位 ID；`CAN_ID_EXT` 为扩展帧 29 位 ID
* `tx.RTR = CAN_RTR_DATA`：数据帧；`CAN_RTR_REMOTE` 为遥控帧（无数据，请求对方发送）
* `tx.DLC`：数据长度 0~8，CAN 2.0 数据帧上限为 8 字节

### 2.2 位同步与采样点

位时序由三个参数决定（PCLK 为 CAN 外设时钟，F407=42MHz / F103=36MHz）：

```text
tq = PCLK / Prescaler
1 bit = 1 + BS1 + BS2 个 tq
波特率 = PCLK / Prescaler / (1 + BS1 + BS2)
采样点 = (1 + BS1) / (1 + BS1 + BS2)
```

本工程两块板的真实配置与计算结果：

| 板子 | PCLK | Prescaler | BS1 | BS2 | 1 bit | 波特率 | 采样点 |
|---|---|---|---|---|---|---|---|
| F407 | 42 MHz | 6 | 11 | 2 | 14 tq | 500 kbit/s | 85.7% |
| F103 | 36 MHz | 4 | 15 | 2 | 18 tq | 500 kbit/s | 88.9% |

关键结论：两块板 Prescaler/BS1/BS2 均不同，但波特率都算得 500 kbit/s，因此能正常组网——节点间只需波特率一致，位时序参数不必相同。采样点越靠后越抗传播延迟，短总线、低抖动下 85.7% 与 88.9% 可兼容。

SJW（同步跳转宽度）允许节点在隐性→显性跳变时微调相位，本工程均为 1TQ。

### 2.3 非破坏性仲裁

CAN 是多主总线，多个节点同时发送时依靠 ID 仲裁：

* 总线上 0（显性）覆盖 1（隐性）
* ID 越小，显性位越靠前，优先级越高，赢得仲裁
* 输掉仲裁的节点自动转为接收，不破坏任何一帧，随后重发

协议中 0x100（主控心跳）优先级高于 0x102/0x202，正符合"主控最关键"的优先级设计。

### 2.4 错误处理三状态

每个节点维护 TEC（发送）与 REC（接收）两个错误计数器：

* 发送错误 +8、接收错误 +1（特殊情形 +8）、成功一次 -1
* 错误主动：TEC<128 且 REC<128，正常发送错误帧
* 错误被动：≥128，只能发被动错误标志（全隐性），别人不一定能识别
* 总线关闭：TEC≥256，节点退出总线，`AutoBusOff=ENABLE` 后硬件自动恢复，恢复前需检测 128 个连续隐性位

Day19 实验 D 中主控拔 CANH 后 REC 累积到 40，正是接收侧错误计数的表现。

### 2.5 过滤器：掩码模式 vs 列表模式

* 掩码模式：`(收到ID & Mask) == (Filter & Mask)`，Mask 为 1 的位必须匹配，为 0 的位不关心，适合过滤一段 ID 范围
* 列表模式：寄存器直接存放精确 ID，只有完全相同才接收，适合过滤几个固定 ID

两个实现细节：

* ID 需左移 5 位（11 位 ID 在过滤器寄存器中右对齐到高位），如 `0x102 << 5`
* 32 位缩放：1 个 Bank = 1 组掩码+ID（或 2 个列表 ID）；16 位缩放：1 个 Bank = 2 组

本工程 F407 用 Bank0 精确收 0x102、Bank1 精确收 0x202（Mask=0x7FF 全比较），Node1 只收 0x101、Node2 只收 0x201。

### 2.6 中断接收与传输策略

接收链路：CAN RX0 中断回调读帧 → `xQueueSendFromISR` 投递队列（ISR 安全）→ 接收任务取出处理。ISR 内不做 printf（Day17 经验）。

三种发送策略：

* 定时发送：周期上报（本工程 1s 心跳/温度/速度）
* 事件触发发送：状态变化才发送，省带宽，适合告警
* 请求/应答：主控发命令帧、从节点收到后回应（预留的 0x101/0x201 即此模式，后续电机控制使用）

## 4. 实验过程（Experiment）

### 实验 1：PCAN-View 发送 0x101

现象：仅 Node1 串口打印 `[NODE1] RX cmd=0x101`，F407 与 Node2 无反应。

验证：Node1 过滤器只收 0x101；CAN 帧广播到所有节点，收不收由各自过滤器决定。

### 实验 2：PCAN-View 发送 0x201

现象：仅 Node2 串口打印 RX 命令，F407 与 Node1 无反应。

验证：Node2 过滤器只收 0x201。

### 实验 3：PCAN-View 发送 0x102

现象：F407 串口打印 `[CAN_RX] node=0` 并更新温度状态，从节点无反应。

验证：F407 双 Bank 过滤器精确接收 0x102；同一帧总线广播、各节点独立过滤。

综合结论：三帧发送全部符合预期，验证了"广播 + 精确过滤"的总线行为。

## 5. 遇到的问题与解决（Problems & Solutions）

### Problem 1：帧 ID 与数据负载概念混淆

问题：首次接触"发一帧 0x101"时，不清楚 0x101 是帧 ID 还是数据。

原因：CAN 帧由 ID（标识符，决定过滤与优先级）与数据负载（0~8 字节内容）两部分组成，两者职责不同。

解决：通过 PCAN-View 实操理解——ID 填 101、DLC 与 Data 随意填写，过滤只认 ID；类比"门牌号（ID）与快递内容（数据）"。

## 7. 工程总结（Engineering Summary）

## 波特率一致即可组网

F407 与 F103 位时序参数不同，但波特率同为 500 kbit/s，所以能通信。组网关键约束是波特率一致，而非参数相同。

## 过滤器是 CAN 应用层的第一道门

CAN 本质是广播，节点靠过滤器决定收不收；应用层协议（帧 ID 分配）必须与过滤器配置配套，否则出现"收不到"或"乱收"。

## 8. 面试问答（Interview Prep）

### Q1：CAN 标准帧与扩展帧的区别？

答题要点：

* 标准帧 11 位 ID、扩展帧 29 位 ID，由 IDE 位区分
* 扩展帧适合节点多、标识符需求大的网络
* 数据帧 DLC 上限 8 字节，超过需上层协议分包（CAN FD 除外）

### Q2：如何计算 CAN 波特率与采样点？

答题要点：

* 波特率 = PCLK / Prescaler / (1 + BS1 + BS2)
* 采样点 = (1 + BS1) / (1 + BS1 + BS2)
* 能现场代入本工程参数（F407：42M/6/14=500k，85.7%）

### Q3：为什么说 CAN 仲裁是非破坏性的？

答题要点：

* 显性（0）覆盖隐性（1），依靠位级监听
* 输掉仲裁的节点自动转为接收、不丢数据、稍后重发
* 对比以太网冲突后随机退避重发

### Q4：CAN 错误处理三状态？

答题要点：

* 错误主动 → 错误被动（计数器 ≥128）→ 总线关闭（TEC≥256）
* 计数规则：发送错误 +8、接收错误 +1、成功 -1
* 总线关闭恢复需 128 个连续隐性位，`AutoBusOff=ENABLE` 自动恢复

### Q5：掩码模式与列表模式的区别？

答题要点：

* 掩码：指定必须匹配的位，适合一段 ID 范围
* 列表：精确 ID 列表，适合几个固定 ID
* 实现细节：ID 左移 5 位；16/32 位缩放决定每 Bank 容纳数量
