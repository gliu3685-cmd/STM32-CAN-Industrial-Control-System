# 面试问答笔记（FreeRTOS / CAN / PID / Bootloader）

> 项目综合复习用，按模块整理高频问题与答题要点。

## 1. FreeRTOS

### Q1：FreeRTOS 任务调度方式？

* 抢占式（高优先级就绪即抢占）+ 时间片轮转（同优先级）
* 任务状态：运行 / 就绪 / 阻塞 / 挂起

### Q2：优先级反转是什么？怎么解决？

* 低优先级任务持锁，高优先级任务等待，中优先级任务抢占导致高优先级被“饿”
* 解决：互斥量（mutex）的优先级继承，把持锁任务临时提到等待者优先级

### Q3：队列、信号量、互斥量、事件组、任务通知怎么选？

* 队列：传递数据（本项目的 xCanRxQueue 传 CAN 帧）
* 二值信号量：ISR 通知任务（如“收到数据了”）
* 计数信号量：资源计数/事件计数
* 互斥量：保护共享资源（本项目 uartMutex 保护串口打印）
* 事件组：多条件 AND/OR 等待
* 任务通知：轻量，省内存，1 对 1

### Q4：ISR 里要注意什么？

* 只能用 FromISR 后缀的安全接口，不能阻塞
* 禁止 printf（本项目 Day13 规则：会与任务打印抢占 UART）
* 中断只做“收数据/置标志”，业务放任务里

### Q5：heap_1 ~ heap_5 区别？

* heap_1：只分配不释放，最简单
* heap_2：按大小释放（有碎片）
* heap_3：包装标准 malloc/free，线程安全
* heap_4：合并相邻空闲块（推荐默认，本项目用）
* heap_5：支持多个不连续内存区

### Q6：栈溢出和 HardFault 怎么定位？

* 栈溢出钩子（vApplicationStackOverflowHook）
* HardFault 现场解析：EXC_RETURN 判断 MSP/PSP，读压栈的 8 个寄存器（PC/LR/R0-R3...），用 addr2line 定位

## 2. CAN

### Q1：CAN 和 UART/RS485 的区别？

* CAN 双线差分（CANH/CANL），多主、非破坏性仲裁，错误检测强，适合工业总线
* UART 点对点；RS485 半双工主从

### Q2：显性/隐性、仲裁原理？

* 显性（0）优先于隐性（1）；多节点同时发送时，隐性位被显性覆盖 → 发隐性的节点退出发送
* ID 越小优先级越高

### Q3：帧类型？

* 数据帧 / 遥控帧 / 错误帧 / 过载帧；标准帧 11 位 ID，扩展帧 29 位

### Q4：波特率与采样点？

* 波特率由 1 位时间（TQ）和位时间分段决定：SYNC_SEG + PROP_SEG + PHASE_SEG1 + PHASE_SEG2
* 采样点一般 70%~80%（本项目 500kbps）

### Q5：错误处理三状态？

* 错误主动（TEC<128）/ 错误被动（128<=TEC<=255）/ 总线关闭（TEC>255，脱离总线）
* 本项目 AutoBusOff=ENABLE 自动恢复，错误回调只恢复 READY，详情读 ESR

### Q6：过滤器掩码模式 vs 列表模式？

* 掩码：一组 ID 按掩码匹配（本项目 Mask=0x7FF 精确收 0x201）
* 列表：逐条精确匹配

### Q7：心跳/离线检测怎么设计？

* 主控 1s 发心跳帧；连续超时（如 5s）判离线，恢复后自动清标志
* 故障注入可区分“单节点离线”与“主控 ACK 错误”（本项目 Day19/21 实测）

### Q8：本项目协议有哪些帧？

* 0x100 心跳 / 0x101 请求温度 / 0x102 温度 / 0x103 MPU6050 加速度 / 0x201 设置速度 / 0x202 RPM 反馈（详见 [can-protocol.md](can-protocol.md)）

## 3. PID

### Q1：P / I / D 各管什么？

* P：按当前误差成比例输出，主导响应
* I：累计历史误差，消除稳态误差
* D：按误差变化率，抑制超调（对噪声敏感）

### Q2：位置式 vs 增量式？

* 位置式输出绝对量，累加全部历史误差，易饱和
* 增量式只输出 Δout，无累积误差，便于限幅与切换（本项目用增量式）

### Q3：积分饱和与处理？

* 执行器饱和时误差持续积分，恢复后严重超调
* 处理：积分限幅、积分分离（|误差|大时关积分）、遇限消积分（本项目用积分分离 + 输出限幅）

### Q4：调参顺序？

* 先 P 找到临界震荡 → 加 I 消稳态误差 → 最后 D 抑超调；一次只动一个参数

### Q5：编码器测速？

* M 法（数脉冲）适合高速；T 法（测周期）适合低速；M/T 混合
* 相邻读数差值可规避 16 位计数器回绕
* 采样周期应 ≤ PID 周期；反馈噪声必须先处理，否则闭环会抖

## 4. Bootloader / IAP

### Q1：IAP 和 ISP 区别？

* ISP：通过芯片自带 Bootloader（串口/USB 等）烧录，需要操作 boot 引脚/复位
* IAP：应用自己实现 Bootloader，运行中升级 APP，无需额外硬件操作

### Q2：Flash 怎么分区？

* Bootloader 区（0x08000000 起，本项目 64KB）+ APP 区（0x08010000 起，960KB）
* 从扇区边界对齐，独立擦写

### Q3：跳转 APP 的步骤？

* 关中断 → 读 APP 向量表初始 MSP → `__set_MSP` → 函数指针跳 APP 的 Reset_Handler
* 跳前校验：初始 MSP 在 RAM 范围 + magic 标志（+0x100 处 0xA5A5A5A5）

### Q4：为什么 APP 要设 VTOR？

* 向量表搬到 0x08010000，不设 VTOR 中断会按 0x08000000 查表 → HardFault

### Q5：升级协议怎么保证可靠？

* 帧头同步（A5 5A）+ 长度 + 单帧 CRC32 + ACK/NACK + 超时重试
* FINISH 时对整段 Flash 重算 CRC32，防漏帧/乱序；校验不过不写 magic → 不会跑损坏固件

### Q6：升级中断电会不会变砖？

* 先擦后写，中断后 APP 区不完整；因 magic 未写，下次启动报 NO APP，可重新升级恢复

## 5. 项目综合

### Q1：项目最大的难点？

* L298N 驱动极性反转（0 占空比全速、满占空刹车）——通过 H 桥逻辑分析定位
* F103 CAN_RX 输入模式配置；编码器 PWM 噪声污染（硬件滤波延后）

### Q2：为什么用 CAN 不用 RS485？

* 多主、非破坏性仲裁、错误检测强、接线简单，贴近工业现场

### Q3：怎么证明是你做的？

* GitHub 仓库有完整提交链、每日学习记录（Day1-40）、协议/架构文档、上位机工具

### Q4：还能怎么扩展？

* CAN IAP（升级走 CAN 总线）、双 Bank 升级、姿态闭环（0x103 接入主控）、更多节点
